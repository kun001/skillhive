# 更新日志维护

公开入口 `/changelog`，无需登录。按部署时间从新到旧展示日期、版本和更新内容，保留可分享的版本锚点。

内容集中在 `web/src/features/changelog/releases.ts`；界面文案在 `web/src/i18n/changelog.ts`。页面随 Web 镜像部署，不依赖数据库或登录接口。

## 每次部署

1. 将本轮用户可感知的变更写为一条记录，提供中英文标题、摘要和变更列表。按从新到旧排列，使用稳定且唯一的 `id`。
2. 构建部署前，填写实际部署日期（`YYYY-MM-DD`）和与本次镜像一致的版本标识；只有构建并切换成功后，这条记录才会随新镜像展示。若部署失败，回滚并移除本轮记录，不保留错误的上线记录。
3. 每条记录都代表一次实际部署，不提供分类筛选或分类标题，不使用待发布、下一次更新、已发布等状态。尚未上线的功能不进入公开日志。
4. 运行 `make typecheck-web`、`make lint-web`，验证 Web 容器中游客访问、版本链接、移动端导航以及中英文展示。后端有变更时同时运行后端检查和相应回归。
5. 部署成功后验证实际域名的日志入口、版本、日期和相关功能，并更新部署记录。没有自动从 Git 提交生成更新日志，提交时间不能当作上线时间。

初始历史内容来自 `deploy/baota/README.md` 中两轮已验证的部署。首次上线覆盖 2026-10-04 至 2026-10-05，使用日期范围；未把早期开发提交拆成虚构的发布版本。
