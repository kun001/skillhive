# 产品定位：团队 Agent 的私有上下文中心

确认日期：2026-10-14。本文记录 SkillHive 的对外定位与取舍，首页、README 与文档站文案以此为准。功能边界仍以 [架构说明](skillhive-architecture.md) 为准。

## 一句话

**团队 Agent 的私有上下文中心**：把团队沉淀的做法（技能）和资料（知识）交给成员正在用的每一个 Agent，按成员权限取用，读写留痕，数据留在自己的服务器上。

English: *The private context center for your team’s agents.*

## 为什么不是“团队共享文件夹”

只做在线文件夹时，在线文档、网盘类产品在编辑、协作、移动端和生态上都更成熟，私有部署这一条不足以让团队迁移。SkillHive 的价值在于**服务团队已经在用的 Agent**，而不是替代给人阅读的文档工具。

| | 在线文档与网盘 | RAG 知识库平台 | SkillHive |
| --- | --- | --- | --- |
| 为谁设计 | 人阅读与协作 | 平台内自建问答机器人 | 团队已在用的 Agent |
| Agent 怎么用上资料 | 下载后粘贴 | 由平台的机器人回答 | MCP 按成员权限直接取用 |
| 做法如何沉淀 | 无统一格式 | 通常不涉及 | `SKILL.md` 技能，经扫描与审核 |
| 治理 | 链接分享为主 | 平台内权限 | Token 按操作、空间、知识库授权，逐次校验，读写审计 |

对外表述：不要求团队替换现有文档工具；需要交给 Agent 的做法和资料放进 SkillHive。

## 三层上下文

1. **技能（怎么做）**：`SKILL.md` 技能包，校验、安全扫描、人工审核后发布，不绑定 AI 工具。
2. **知识（用什么做）**：按团队和文件夹组织的文件，版本可追溯，原样交给 Agent 阅读。
3. **边界（能碰什么）**：最小权限 Token、每次调用重新校验、管理员不越过团队边界、读写审计、写入不覆盖且删除只归档。

## 目标用户

优先面向**已在使用编程类或通用 Agent、且有私有化或合规要求的团队**，研发团队是首批用户：他们最先感到“Agent 不认识团队”的痛点，也最熟悉技能这种形态。

## 明确不做

- 文档在线编辑与多人协作（继续交给团队现有工具）。
- 平台内的聊天问答机器人、向量检索和 RAG。
- 在平台内执行技能脚本。

## 能力规划

能力缺口的取舍已于 2026-10-15 确认：知识库可以提取文本、用大模型生成摘要并做全文检索，但不做向量检索和 RAG；“大纲 + 按章节读取”不纳入计划。分三步推进，见 [Agent 上下文能力路线图](29-agent-context-roadmap.md)。

## 如何验证定位

- 观察 MCP 读取量与网页访问量的比例；Agent 读取持续增长，说明定位成立。
- 与 5～10 个目标团队访谈，确认他们愿意把“交给 Agent 的资料”单独放进 SkillHive。
