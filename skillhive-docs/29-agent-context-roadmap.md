# Agent 上下文能力路线图

确认日期：2026-10-14。本文落实 [产品定位](28-product-positioning.md) 中“团队 Agent 的私有上下文中心”所需的能力，分三步推进。每一步上线日期以更新日志为准。

## 约束调整

知识库原约束为“不做内容解析、向量检索或 RAG 问答”。为了让 Agent 读得懂、找得到，调整为：

- **允许**：提取文件文本并保存为 Markdown 文本版本；用可配置的大模型为每个文件生成摘要和关键词；对标题、描述、摘要和正文做全文检索。
- **仍不做**：向量检索、分块召回、平台内的 RAG 问答或聊天机器人；扫描件 OCR；在线编辑。

## 三步总览

| 步骤 | 目标 | 内容 |
| --- | --- | --- |
| 第一步（v0.4） | 让 Agent 读得懂、找得到 | Markdown 文本提取；大模型摘要；全文检索优化；团队说明书 |
| 第二步（v0.5） | 把技能和资料串起来 | 技能引用知识文件；技能以 MCP 提示词形式出现在客户端；资料负责人与复核日期，过期时提醒 Agent |
| 第三步（v0.6） | 治理与价值证明 | Agent 使用洞察；知识库或文件级“禁止 Agent 读取”开关；标记 Agent 写入的内容 |

曾评估“大纲 + 按章节读取”，因 Agent 通常一次读完整文件、按章节切分收益有限，不再纳入计划。

## 第一步：让 Agent 读得懂、找得到

### 1. Markdown 文本提取

**范围**：只用最简单、可靠的提取方式，提取不了的直接跳过。

| 文件类型 | 处理方式 |
| --- | --- |
| `md` `markdown` `mdx` `txt` `csv` `json` | 原文即文本 |
| `docx` | Apache POI 读取段落与表格；标题样式转为 `#` 层级，列表转为 `-`，表格转为 Markdown 表格 |
| `pptx` | 每页一节 `## Slide N`，提取文本框、表格和备注 |
| `xlsx` | 每个工作表一节，转为 Markdown 表格（行列设上限） |
| `pdf` | Apache PDFBox 按页提取文本层；几乎没有文字的视为扫描件，标记为不支持 |
| 其他（`doc` `xls` `ppt`、图片、压缩包等） | 标记为不支持 |

**流程**：

1. 上传新文件、上传新版本或恢复历史版本时，在同一事务中为该版本登记提取任务。上传照常立即发布，不等待提取。
2. 后台任务通过租约认领任务（与技能介绍生成相同的模式），读取原文件，提取后保存 Markdown、字数和分词结果。
3. 迁移时为现有文件的当前版本补登记任务，上线后自动补齐。

**数据**：新表 `knowledge_document_text`，以文件版本为主键，记录状态（待处理、处理中、完成、不支持、失败）、尝试次数、租约、提取器标识、Markdown 正文、字数、是否截断和错误码。

**限制**：只处理 30 MiB 以内的文件；正文最多保留 50 万字，超出部分截断并标记；解析使用 POI / PDFBox 的安全默认设置，不执行宏或脚本，加密文件视为不支持。

**权限**：文本版本与原文件同权：需要团队成员身份和下载权限，读取记入审计（`KNOWLEDGE_DOCUMENT_TEXT_READ`，注明是否通过 Token）。

**接口**：

- `GET /api/v1/knowledge/documents/{id}/text?version=N`：返回状态、摘要、关键词和 Markdown 正文。
- MCP `read_document` 新增 `format` 参数：`auto`（默认，有文本版本时返回 Markdown，否则返回原文件）、`markdown`、`original`。

### 2. 大模型摘要

**用途**：为每个文件生成一段摘要和若干关键词，用于搜索命中、搜索结果展示和帮助 Agent 判断是否需要读全文。

**流程**：文本提取完成后，若启用摘要，则登记摘要任务；后台任务把标题和正文前若干字发给配置的模型，要求返回 JSON：`summary`（与文件同语言，中文约 80～150 字）和 `keywords`（3～8 个）。失败按退避重试，用尽次数后标记失败，不影响文本版本使用。

**配置**：`skillhub.knowledge.summary.*`，与技能介绍生成一致，使用 OpenAI 兼容的 `/chat/completions` 接口；**默认关闭**。私有部署时应指向自建模型（例如本机 LM Studio、vLLM），因为启用后文件内容会发送给该模型。思考型模型（如 LM Studio 中的 Qwen3）需设置 `reasoning-effort: none`，否则输出预算会被思考过程耗尽。启用前已提取文本的文件，会由摘要任务分批补登记。

**安全**：文件内容按不可信数据处理，提示词要求模型忽略其中的指令；不记录模型响应、文件内容或凭据。

**数据**：新表 `knowledge_document_summary`，以文件版本为主键，结构与 `skill_introduction` 一致，另存关键词。

### 3. 全文检索优化

现有跨知识库搜索只对标题和描述做 `LIKE` 匹配，按更新时间排序。改为：

- **匹配范围**：标题、描述、摘要与关键词、Markdown 正文。
- **中文分词**：在应用内切分：中文、日文、韩文连续字符按相邻两字切分，字母和数字按单词切分；写入 PostgreSQL `simple` 配置的 `tsvector` 并建 GIN 索引。无需数据库扩展，官方 `postgres:16-alpine` 镜像可直接使用。
- **查询**：每个空格分隔的关键词按“相邻两字的短语”匹配，等价于子串匹配；多个关键词需同时命中。单个汉字按前缀匹配。
- **排序**：标题命中 > 摘要或关键词命中 > 描述命中 > 正文命中，同档按正文相关度和更新时间。
- **结果**：每条结果附摘要和正文命中片段，Agent 无需逐个读取就能判断相关性。
- **范围**：权限过滤先于分页，与现有规则一致；只检索当前发布版本。

### 4. 团队说明书

每个团队空间维护一份 Markdown 说明（最多 2 万字）：团队约定、目录导览、常用技能、注意事项。Agent 第一次连接时先读它，就能知道“这个团队的东西在哪里、该怎么用”。

- **数据**：新表 `namespace_guide`，以团队空间为主键，记录内容、更新人和更新时间。
- **权限**：团队成员可读；团队所有者和管理员可编辑；编辑记入审计。Token 读取时同样受团队成员身份和 Token 的团队空间范围约束。
- **接口**：`GET/PUT /api/v1/namespaces/{slug}/guide`；MCP 新增 `get_team_guide`，任一读取权限即可使用；`initialize` 提示 Agent 先读取所在团队的说明书。
- **网页**：团队空间页展示说明书，所有者和管理员可编辑。

### 验收

- 上传 docx、pptx、xlsx、pdf、md 后，文本版本自动生成；扫描件和不支持的格式标记为不支持，原文件读取不受影响。
- 启用摘要（本地 LM Studio）后，文件获得摘要和关键词；关闭时搜索和读取照常可用。
- 用正文中的中文短语能搜到文件，结果带摘要和命中片段；无权访问的文件不出现在结果和总数中。
- MCP `read_document` 默认返回 Markdown；`get_team_guide` 返回团队说明书；撤销下载权限后文本版本同样不可读。
